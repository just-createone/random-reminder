# 随机提醒器产品路线

本文档用于确定随机提醒器从个人可用工具发展为可公开测试、可持续运营和可商业化产品的实施路线。

当前版本：`v0.1.3`

---

## 一、产品定位

随机提醒器是一款帮助用户在一天中的随机时间接收自定义内容提醒的工具。

它不是传统的固定闹钟，而是通过随机时间触发，让用户在不确定的时刻重新看到自己关心的内容。

典型提醒内容包括：

- 自我激励语句
- 学习知识点
- 工作原则
- 健康习惯
- 戒除不良习惯提示
- 情绪调节语句
- 个人目标
- 重要事项
- 创作灵感
- 复习卡片

---

## 二、目标用户

### 第一阶段用户

个人使用者，主要包括：

- 需要习惯提醒的人
- 需要随机复习知识的人
- 希望保持目标感的人
- 容易忘记长期计划的人
- 需要间歇性心理提示的人
- 希望建立个人语录库的人

### 第二阶段用户

具有明确使用场景的小群体：

- 雅思、考研和职业考试学习者
- 健身和减脂用户
- 自律打卡用户
- 内容创作者
- 企业团队管理者
- 教练、咨询师和培训师

---

## 三、核心问题

产品主要解决以下问题：

1. 固定时间提醒容易被用户忽略。
2. 普通提醒工具不适合展示大量自定义内容。
3. 用户很难长期记住自己的目标、原则和计划。
4. 学习内容缺少低压力的随机复习方式。
5. 现有提醒工具通常缺少个人内容库和随机调度能力。

---

## 四、核心价值

随机提醒器的核心价值是：

```text
在合适的时间范围内，
以不可预测的方式，
重新呈现用户主动选择的重要内容。
```

产品应始终围绕以下原则设计：

- 创建提醒要简单
- 提醒触发要可靠
- 用户数据要安全
- 配置过程要容易理解
- 手机端使用要方便
- 不增加不必要的复杂功能

## 七、功能优先级

使用以下优先级：

### P0：必须完成

影响产品基本可用性或数据安全：

- 提醒可靠触发
- 数据持久化
- 备份和恢复
- 通知权限处理
- 异常提示
- 基础部署
- 稳定性验证

### P1：公开测试前完成

明显影响普通用户体验：

- 编辑提醒
- 启用和停用单条提醒
- 提醒分类
- 数据导入和导出
- 手机端界面优化
- 首次使用引导

### P2：用户验证后决定

需要根据真实反馈判断：

- 提醒模板
- 批量操作
- 数据统计
- 自定义主题
- 高级随机规则
- 提醒历史分析

### P3：商业化阶段

需要账号和云服务支持：

- 多设备同步
- 云端推送
- 订阅支付
- 团队功能
- 管理后台

## 八、商业化假设

现阶段不直接开发支付系统，先验证用户是否愿意长期使用。

需要验证的假设：

1. 用户是否真的需要随机提醒，而不只是固定闹钟。
2. 用户是否会主动创建十条以上提醒。
3. 用户是否会连续使用七天以上。
4. 用户是否需要跨设备同步。
5. 用户是否愿意为云同步付费。
6. 用户最常创建哪一类提醒。
7. 用户是否需要模板库。
8. 用户是否愿意导入自己的学习资料。

## 十、首批用户验证

第一批测试用户建议控制在：

```text
5 至 10 人
```

优先选择：

- 愿意连续使用一周的人
- 能够描述真实使用场景的人
- 愿意反馈问题的人
- 不需要开发指导也能尝试使用的人

需要记录：

- 用户为什么使用
- 创建了多少条提醒
- 使用了多少天
- 哪些通知被忽略
- 哪些操作难以理解
- 是否遇到数据丢失
- 是否愿意继续使用
- 是否愿意推荐给他人
- 最希望增加什么功能

## 十一、核心验证指标

公开测试阶段重点观察：

| 指标           | 说明                       |
| -------------- | -------------------------- |
| 首次创建成功率 | 新用户是否能创建第一条提醒 |
| 次日留存       | 第二天是否继续打开         |
| 七日留存       | 七天后是否仍然使用         |
| 人均提醒数量   | 用户实际维护多少条提醒     |
| 通知触达率     | 提醒是否正常发送           |
| 通知点击率     | 用户是否会打开提醒         |
| 数据故障数量   | 是否出现数据丢失或损坏     |
| 部署成功率     | 用户是否能按文档完成部署   |
| 问题反馈数量   | 哪些环节最容易失败         |

现阶段不追求大量用户，优先保证真实反馈质量。

## 十三、开发约束

后续开发必须遵守：

1. 每个版本只解决一组明确问题。
2. 新功能必须对应真实用户需求。
3. 不为了展示技术而增加复杂架构。
4. 数据安全优先于界面效果。
5. 移动端体验优先于桌面端扩展。
6. 核心提醒可靠性优先于功能数量。
7. 所有重要功能必须有测试。
8. 每个阶段完成后必须提交 Git。
9. 发布版本前必须完成备份。
10. 商业化功能必须建立在用户验证之上。

---
